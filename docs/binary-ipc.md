# Zero-Macro Raw Binary IPC (`RawBytes` & `Meta<T>`)

FORGE v0.4 transfers binary buffers (`Uint8Array` / `ArrayBuffer` ↔ `forge::RawBytes`) directly over `application/octet-stream` without JSON array inflation, Base64 overhead, or procedural macros.

---

## 1. Purpose & User-Facing Behavior

- Send and receive arbitrary binary payloads (images, audio chunks, SQLite snapshots, encrypted blobs) across both `webview` and `cef` runtimes at native memory speed.
- Attach structured JSON arguments alongside raw binary payloads via the `Meta<T>` header extractor (`X-Forge-Meta`) without writing custom byte-framing code.

---

## 2. Public Interface

### Rust (`forge::RawBytes` & `forge::Meta<T>`)

- **`RawBytes(pub Vec<u8>)`** — Zero-macro command payload and/or reply wrapper. Supported across all 6 `CommandHandler` combinations (`() -> RawBytes`, `Req -> RawBytes`, `RawBytes -> Res`, `RawBytes -> RawBytes`, plus `0..=4` `FromContext` extractors).
- **`Meta<T>(pub T)`** — `FromContext` extractor deserializing `T: DeserializeOwned` from the `X-Forge-Meta` header (`uri:<percent-encoded-json>` or raw UTF-8 JSON).
- **`HeadlessApp`** — `invoke_raw(cmd, bytes)`, `invoke_raw_as(win, cmd, bytes)`, `invoke_raw_with_meta(cmd, meta, bytes)`, `invoke_json_to_raw(cmd, payload)`.

### JavaScript / TypeScript (`window.forge`)

- `window.forge.invoke(cmd, uint8OrArrayBuffer, meta?)` — Automatically sends `Content-Type: application/octet-stream` when given a typed array or `ArrayBuffer`, and automatically resolves to `Uint8Array` when the Rust handler returns `RawBytes`.
- `window.forge.invokeBytes(cmd, payload?, meta?): Promise<Uint8Array>` — Typed helper alias generated by `forge bindings`.
- Built-in `AppFsPlugin` binary commands: `fs.read_bytes` (`{ path }` → `Uint8Array`) and `fs.write_bytes` (`Uint8Array` + `meta = { path }`).

## 3. Minimal Example

**Rust (`src/main.rs`)**
```rust
use forge::{App, ForgeError, Meta, RawBytes};
use serde::Deserialize;

#[derive(Deserialize)]
struct SaveImageMeta {
    name: String,
    invert: bool,
}

async fn process_image(
    Meta(meta): Meta<SaveImageMeta>,
    mut bytes: RawBytes,
) -> Result<RawBytes, ForgeError> {
    if meta.invert {
        for b in &mut bytes.0 {
            *b = !*b;
        }
    }
    Ok(bytes)
}

fn main() -> forge::Result<()> {
    App::new().command("image.process", process_image).run()
}
```

**TypeScript (`src-ui/App.tsx`)**
```ts
const input = new Uint8Array([0x00, 0x7f, 0xff]);
const output = await window.forge.invokeBytes("image.process", input, {
  name: "preview.bin",
  invert: true,
});
```

## 4. Limitations & Security Invariants

- **Trait Coherence Invariant:** `RawBytes` intentionally does not implement `serde::Serialize` or `serde::Deserialize`, guaranteeing unambiguous type inference alongside standard JSON `async fn` handlers.
- **Single Choke Point Security:** Binary `/__forge_ipc/*` calls pass through the exact same `POST`, `Sec-Fetch-Site`, constant-time `X-Forge-Token`, `PermissionPolicy::check`, and `CatchUnwindFuture` gates as JSON IPC.
- **Strict Content-Type Validation:** Invoking a `RawBytes`-expecting command with `application/json` (or vice versa) fails deterministically with HTTP `400` (`FORGE_INVALID_PAYLOAD`).
